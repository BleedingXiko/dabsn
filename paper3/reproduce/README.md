# Paper 3 reproduction

`matrix_protocol.json` declares every run in the study. It is generated by
`matrix.py`, and `run.py` executes it.

| File | Role |
|---|---|
| `tasks.py` | MQAR (Zoology), copying and selective copying (S4/Mamba), passkey (Mohtashami & Jaggi), key-value recall with the query late or early; distance and load axes |
| `models.py` | NoPE, RoPE (+ test-time PI and YaRN, and YaRN fine-tuned), ALiBi, sliding-window NoPE, Infini-attention, and the single `DABSNHostMemory` insert (front, middle or back), plus a parameter-matched MLP control at the same place |
| `matrix.py` | The declared grid → `matrix_protocol.json` |
| `run.py` | Resumable executor: `probe`, `plan`, `run`, `status`, `collect` |

```bash
pip install .            # from the repository root
python paper3/reproduce/run.py run --out results/paper3
```

## Tasks

Each task uses its published generator unchanged at the training length.

- **MQAR.** Arora et al. (2023), `zoology/data/multiquery_ar.py`: vocabulary
  8192, keys from the lower half and values from the upper half, the
  key-value block first, then the keys queried at power-law gaps
  (`power_a = 0.01`), with uniform random tokens at every other position.
  Training mixes Zoology's three length-256 configurations (16, 32 and 64
  pairs) in equal shares.
- **Copying.** `torch_copying_data` from the S4 repository: Arjovsky et al.'s
  copying task with 10 tokens over 8 symbols, then noise, then 10 markers, at
  which the tokens are reproduced in order.
- **Selective copying.** The same generator with `variable=True`: Gu & Dao's
  selective copying with 16 tokens over a 16-token vocabulary, scattered at
  random positions among noise.
- **Passkey.** The prompt of Mohtashami & Jaggi (2023), word-tokenized: the
  task description, the repeated "The grass is green. ..." text, the
  information line at a uniformly random depth, and the question. The key is
  uniform in [1, 50000], and its digits are predicted.
- **Key-value recall** (mechanism study, memory models only): one query over
  the Zoology key and value vocabularies, asked after the pairs.

## Protocol

- **Training to convergence.** Synthetic runs use a constant rate after warmup
  and stop once held-out validation accuracy reaches 99% at two consecutive
  checks, or at 30,000 steps. Every check is logged as a learning curve.
- **Learning rates.** Every model is trained on every task at each declared
  rate with seed 0. The rate with the best in-distribution validation accuracy
  (validation loss for the language model) is then used for seeds 1 and 2.
  Seed 0 at that rate is the sweep run itself. If the best rate lies at an
  edge of the grid and has not solved the task, one further rate past that
  edge (1e-4 or 1e-2, Zoology's sweep range; 1e-4 or 4e-3 for the language
  model) is trained and joins the selection, so no selected rate is an
  unexplored edge. Test axes are never used for selection.
- **Evaluation data.** Every model sees byte-identical evaluation sequences.
  They derive from a fixed evaluation seed, the axis, the axis value and the
  sample index.
- **Distance.** The content is held at the largest training load, and each
  task's own filler is inserted between the facts and their use, at 1× to 64×
  the training length. The filler is uniform random tokens for MQAR and
  key-value recall (excluding the sequence's own keys, so every query keeps a
  single answer), the noise token for the copying tasks, and the garbage text
  for passkey.
- **Load.** More items with the filler held at its training size. For MQAR
  this reproduces Zoology's own test configurations (512 tokens with 128 pairs,
  1024 with 256) and extends them to 2048 with 512.
- **RoPE.** Checkpoints are also evaluated with position interpolation and
  YaRN applied at test time. Each converged RoPE model is additionally
  fine-tuned with YaRN at 4× the training length (the standard recipe) and
  evaluated on the same grid.
- **Memory placement.** Both memory models (NoPE and sliding-window) insert
  their single memory at the front, before the first block, and the
  parameter-matched control sits at the same place. On MQAR both are also
  trained with the memory in the middle (before block L/2, with the control
  there too), and NoPE with the memory at the back, after the last block.
- **Mechanism.** Memory runs record the admitted bank and the read work per
  sample (batch size 1) at every distance. Each trained key-value recall model
  (every seed) is then tested, without further training, on the same
  sequences with the query also shown before the pairs: the query and its key
  are placed at the start and the last two filler tokens dropped, so the
  length, the pairs and the question at the end are unchanged. Accuracy, the
  admitted bank and the read work are recorded per sample for both versions.
- **Language model.** Character-level enwik8, using the standard 90M/5M/5M
  split. The model is trained at a short context. Loss is reported by
  position out to 32× the training length, along with passkey retrieval using
  the exact Mohtashami & Jaggi prompt.
- **Extreme length.** Passkey checkpoints are evaluated out to 2²⁰ tokens.
  Results are recorded per length. A length that runs out of memory, or that
  would exceed its time limit, is reported as such.
- **Scale.** MQAR is repeated at width 256 and 8 layers, with its own
  learning-rate sweep and seeds.

## Resuming

All artifacts are written atomically. Training data is a pure function of
(seed, step). Checkpoints carry the model, optimizer, gradient scaler and step,
and are written every five minutes by default. Re-running the same command
skips finished work and continues interrupted runs on an identical schedule.
Evaluation resumes item by item. A run that fails is recorded in `error.json`,
and the remaining matrix continues.
